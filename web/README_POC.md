# PoC веб-версии (Фаза 0) — замер FPS в WASM

Цель PoC: собрать игру под веб через **pygbag** «как есть» и получить **реальный FPS
рейкастера в браузере (WASM)**. Нативный ориентир (CPython+numpy, только рендер): **~34 FPS**.

`web/main.py` — временный харнесс: async-обёртка вокруг игрового цикла, которая
стартует сразу в игровой уровень и печатает в консоль браузера строки
`POC_FPS ...` и итог `POC_RESULT avg=... min=... max=...`. Это не продакшн-точка входа
(она появится в Фазе 1), а инструмент замера.

## Как запустить локально (нужен интернет к pygame-web.github.io)

```bash
bash web/build_poc.sh
# открой http://localhost:8000 в Chrome/Firefox
# F12 -> Console -> смотри POC_FPS / POC_RESULT
```

FPS-кап снят намеренно — харнесс крутит рендер на максимуме, чтобы измерить
пропускную способность. Через ~600 кадров он печатает `POC_RESULT` и останавливается.

## Что уже проверено на этапе сборки (в облачном контейнере)

- ✅ pygbag 0.9.3 пакует игру без правок: 87 файлов (весь `src/` + `assets/`).
- ✅ Относительные пути `assets/...` монтируются корректно.
- ✅ **Аудио**: pygbag сам транскодирует `.wav` → `.ogg` и предупреждает о `.wav`
  в `src/audio.py` и `src/config.py`. Вывод для Фазы 1: ссылаться на `.ogg`.
- ✅ Async-харнесс (в обход блокирующего `App.run`, сразу в `GameplayScene`) собирается.
- ⚠️ Косметика сборки: предупреждение о дубле имён из-за авто-стабов `*-pygbag.py`.
- ❌ **Не удалось запустить в браузере в облаке**: сетевая политика окружения
  блокирует `pygame-web.github.io` (403), откуда pygbag берёт шаблон и WASM-рантайм.
  Поэтому замер FPS делается локально (эта инструкция) либо после добавления хоста
  в Allowed domains окружения.

## Замеряем в облаке вместо локалки?

Добавить `pygame-web.github.io` в **Allowed domains** окружения
(меню облачного окружения в заголовке сессии → Edit; оставить галку пакетных
менеджеров). Шаги: https://code.claude.com/docs/en/cloud-environments#network-access
После этого тот же `web/build_poc.sh` + headless-Chromium дадут цифру прямо здесь.
